# F1 E1002 Static Hub

A static Formula 1 information hub designed for a **Seeed Studio reTerminal E1002** and **Home Assistant**.

The main goal is simple: **the E1002 should not have to wait for F1 APIs, weather APIs, or remote image generation every time it wakes up**.

Instead, GitHub Actions does the slow work in the background and publishes ready-made static files. The E1002 only downloads an already-generated 800 × 480 BMP.

---

## What this repository creates

### E1002 pages

The repository maintains four 800 × 480 BMP pages:

| File | Purpose |
|---|---|
| `calendar.bmp` | Next Grand Prix, session schedule, circuit information and current weather |
| `teams.bmp` | Teams, drivers and championship points |
| `standings.bmp` | Driver and constructor championship leaderboards |
| `last-race.bmp` | Previous Grand Prix podium and top-10 result |

`calendar.bmp` and `teams.bmp` are mirrored from the public **InkyCloud-F1** service.

`standings.bmp` and `last-race.bmp` are generated by this repository from the **Jolpica F1 API**.

### Home Assistant page

`homeassistant.html` provides a larger interactive F1 dashboard with four tabs:

- **Next race**
- **Standings**
- **Last race**
- **Teams & drivers**

All F1 data is already embedded into the generated HTML. The Home Assistant page does not need to call the F1 APIs when it loads.

### Additional files

- `f1-data.json` — normalized F1 data for future integrations
- `index.html` — GitHub Pages landing page with previews of all E1002 screens
- `data/update-status.json` — latest update status
- `data/source-etags.json` — saved InkyCloud ETags for conditional downloads

# Architecture

```text
InkyCloud-F1                  Jolpica F1 API
     │                              │
     │ calendar.bmp                 │ race calendar
     │ teams.bmp                    │ standings
     │                              │ last race results
     └──────────────┬───────────────┘
                    │
                    ▼
             GitHub Actions
                    │
          scripts/update_f1_pages.py
                    │
        ┌───────────┼────────────┐
        ▼           ▼            ▼
   static BMPs   static HTML   f1-data.json
        │           │
        ▼           ▼
      E1002     Home Assistant
```

The battery-powered E1002 does **not** perform the F1/weather processing. It simply downloads a static file from GitHub Pages.

# First update

After uploading the repository:

```text
Actions
→ Update F1 E1002 Static Pages
→ Run workflow
```

The first successful run will:

1. download the latest InkyCloud calendar page;
2. download the current teams/drivers page;
3. fetch the current F1 calendar from Jolpica;
4. fetch current driver standings;
5. fetch current constructor standings;
6. fetch the latest completed race result;
7. generate `standings.bmp`;
8. generate `last-race.bmp`;
9. generate `f1-data.json`;
10. generate the Home Assistant dashboard;
11. regenerate the GitHub Pages landing page;
12. commit the changed files back to the repository.

# Automatic update schedule

The workflow runs every hour at approximately 12 minutes past the hour:

```cron
12 * * * *
```

This is intentional.

The original next-race page includes **current weather**, and InkyCloud itself regenerates its calendar and teams output hourly. Updating the static mirror hourly therefore gives the E1002 a reasonably fresh page without making the E1002 itself do any extra processing.

GitHub Actions schedule timing is not guaranteed to start at the exact minute, but exact timing is not important for this use case.

If a less frequent update is preferred, edit:

```text
.github/workflows/update-f1-pages.yml
```

For example, every three hours:

```cron
12 */3 * * *
```

# Why this should load faster on the E1002

The original direct page was:

```text
https://f1.inkycloud.click/calendar.bmp?lang=en&tz=Asia/Singapore&display=spectra6&weather=true&weather_type=current
```

That endpoint may need to resolve the requested configuration and serve an image generated from F1 and weather information.

With this repository the E1002 instead requests:

```text
https://vasanthan1276.github.io/f1-e1002/calendar.bmp
```

The image already exists as a static GitHub Pages file.

The expensive work happens while the E1002 is asleep.

# InkyCloud ETag support

InkyCloud exposes strong ETags for its calendar and teams BMP responses.

This project stores the last ETag values in:

```text
data/source-etags.json
```

On later GitHub Action runs it sends `If-None-Match`.

If the upstream image has not changed, InkyCloud can return:

```text
304 Not Modified
```

and the existing local BMP remains untouched.

This reduces unnecessary downloading and prevents meaningless Git commits.

# F1 data source

Structured data is retrieved from the Jolpica F1 API using the current season.

The script obtains:

- season race calendar;
- driver championship standings;
- constructor championship standings;
- latest race results.

The year is chosen automatically using the configured timezone.

No hard-coded driver or team list is required.

# Main script

The complete update logic is in:

```text
scripts/update_f1_pages.py
```

It intentionally keeps all server-side generation in one file to make future maintenance easier.

The script uses:

- `requests` for HTTP/API access;
- `Pillow` for the locally generated 800 × 480 BMP screens;
- Python `zoneinfo` for Singapore-time conversion.

---

# Design principles

This project follows the same design principle used for the other E1002 static pages:

> Perform processing in GitHub, not on the battery-powered display.

The E1002-facing content therefore has:

- no JavaScript;
- no runtime API request;
- no weather lookup;
- no F1 API lookup;
- no image composition work;
- no delayed rendering.

It simply retrieves a finished BMP file.

The Home Assistant page can use JavaScript only for instant local tab switching. All actual F1 data is already embedded into the generated HTML.

# Troubleshooting

## Placeholder image still appears

Run:

```text
Actions
→ Update F1 E1002 Static Pages
→ Run workflow
```

Then check the workflow log.

## Workflow cannot push changes

Check:

```text
Settings
→ Actions
→ General
→ Workflow permissions
→ Read and write permissions
```

## GitHub Pages shows 404

Check:

```text
Settings
→ Pages
→ Deploy from branch
→ main / root
```

Wait a few minutes after the first deployment.

## E1002 still shows an old page

Confirm the BMP first in a normal browser.

If the browser has the new page but the E1002 still shows an old page, allow the E1002 to complete another normal wake/refresh cycle.

## One upstream source is temporarily unavailable

A workflow failure does not erase the previously generated static page. The last successfully committed BMP remains available through GitHub Pages.
